# 课程匹配度估算算法

> ⚠️ **本文件是检索线索与核对清单，不是数据结论。**
> 其中的流程、数字、机构名、字段口径都必须由 agent **实时联网核验官网**后才可引用；
> 模型记忆只能决定"去哪里查、查什么"，不得直接充当数据。详见 SKILL.md「铁律零：零记忆交付」。

输出三样东西：**0-100 分 + 高/中/低档 + 逐条解释**。只给分不给解释视为未完成。

## 第 1 步：拆项目要求

从项目官网提取两类信息：
1. **先修要求（entry requirements）**：如"quantitative background"、"background in geography/computer science"
2. **课程设置（programme structure）**：核心模块列表，如 GIS Foundations / Spatial Databases / Remote Sensing / Statistics

## 第 2 步：课程归类

把用户每门课映射到上述要求/模块，三档：

| 类型 | 定义 | 示例 |
|---|---|---|
| 核心匹配 | 直接覆盖先修要求或核心模块 | 《GIS原理》→ GIS Foundations；《概率统计》→ quantitative background |
| 加分匹配 | 不在硬性要求里但增强竞争力 | 《Python 程序设计》《数据库》《城市规设原理》《测量学》 |
| 未覆盖 | 项目要求了但用户没修的 | 项目要求编程基础，用户只修过 C 语言且成绩低 |
| 先修风险 | 未覆盖项命中**硬性先修**（entryReq.prereq 且 prereqHard=true）→ 解释行 type 必须写"先修风险"，页面会叠加橙色警示标；宁可高标不可漏标 | 项目要求工程/CS 背景，仅一门 Python 不足以证明；或要求德语 B2 而用户零基础 |

映射规则：
- 一门课可以同时命中多个模块（写多行）
- 成绩 ≥85 满覆盖；70-84 部分覆盖（解释里注明"成绩中等"）；<70 弱覆盖（解释里如实写）
- 项目名称含糊的（如"relevant discipline"）按学科大类判断，解释里说明推断依据

## 第 3 步：打分

```
核心覆盖得分 S1 = (覆盖的核心模块权重和 / 核心模块总权重) × 60
加分覆盖得分 S2 = min(加分匹配课程数 × 5, 25)
成绩水平得分 S3 = 用户相关课程平均分 / 100 × 15（相关课 = 核心匹配∪加分匹配）

匹配分 = S1 + S2 + S3，四舍五入
档位：高 ≥75；中 55-74；低 <55
```

注意：
- 核心模块缺一半以上时，无论加分课多少都封顶 55 分（避免"水课凑分"）
- 用户未提供成绩的课按 80 分保守计，档案卡标注该假设

## 第 4 步：本科对标校准（拿用户本科课，去比该校同专业本科的核心课）

**原则：招生官评估你背景的默认标尺是"我们自家本科同专业毕业生学了什么"。** 只对齐硕士项目模块不够——硕士页的模块列表往往又短又泛，必须再对一次该校自家本科的课程结构：

1. **找对标本科**：在目标学校官网找与所申硕士**同专业/最近邻的本科项目**（申 KU Leuven 城市主义硕士 → 对标其相邻本科；申 AUS 土木硕士 → 对标 AUS 土木工程本科）。没有同名就选课程结构最接近的，解释里写明选择依据。把本科项目名 + 课程结构页 URL 记入该条数据的 `bachelorBenchmark` 字段。
2. **提取其本科核心课清单**（官方 study guide / curriculum 页，一般 15–25 门），逐门对照用户成绩单，按第 2 步三档判定（部分覆盖按 0.5 门计）：
   ```
   本科对标覆盖率 = 用户已覆盖课程数（部分覆盖×0.5） / 对标核心课总数
   ```
3. **校准规则**（对第 3 步匹配分做加减，不超过 ±8）：
   - 覆盖率 ≥ 80%：不加不减，解释写"背景与该校同专业本科生基本同构"
   - 60%–79%：匹配分 −0～−3，逐条列出缺口课
   - < 60%：匹配分 −4～−8，**必须列出全部缺口核心课**；缺口含数学/力学/编程/统计类硬核课时，**额外叠加先修风险**（解释 type 写"先修风险"，页面自动打橙色警示）
4. **写解释**：对标结论进 `match.explanations`（type 写"本科对标"），示例：
   ```
   本科对标：AUS 土木工程本科核心课 18 门，覆盖 13 门（72%）—— 缺《流体力学》《土力学》《工程经济学》，建议 PS 说明相关项目经历或补修
   ```
5. **诚实边界**：官网找不到对标本科或没有课程结构页 → 如实标"对标本科课程结构未取得官方页（待核验）"，按第 3 步原始分交付并注明未校准；**不许拿别校课程清单或模型记忆凑数**。

## 第 5 步：学分换算与总量门槛校验（申请资格的硬性一环）

很多硕士项目（尤其欧陆）在均分线之外还有**学分总量门槛**：如高级硕士常要求 240 ECTS（对应至少 4 年本科）、普通硕士要求 180 ECTS；中国五年制本科总学分通常充足，但**换算口径必须以校方官方页为准**。

1. **提取门槛**：从项目 admission requirements 页提取 `entryReq.creditReq`（ECTS 或当地学分制总量、学制年限要求、是否接受跨阶段直申），带 source + verifiedAt。查不到明示门槛就写"该项目无明示学分总量门槛（以招生办答复为准）"——照样要向招生办邮件确认。
2. **换算参考（仅作 AI 估算起点，禁止当官方结论）**：
   - 中国 1 学分 ≈ 一学期每周 1 学时（约 16 学时）；1 ECTS ≈ 25–30 小时总学习量（官方常用 27–28）
   - 常见落点：中国学分 × 1.5 ≈ ECTS（按 60 ECTS/年 对 40 中国学分/年折算）；**个别学校自定换算或只认 NUFFIC/学信网等认证结果**——以校方页为准，找不到就标待核验
3. **校验与呈现**：
   - 档案填 `profile.credits`（总学分 + 每学分学时）；页面按 `meta.creditConversion`（默认 1 ECTS=27h）估算 ECTS 当量对照门槛，给出"估算满足 / 估算不足（AI 估算）"
   - 估算不足时如实显示，并在解释里给补救口径（预科/研究生文凭衔接、部分学校允许工作经历或额外课程补 ECTS——须官方页佐证）
   - 估算满足也不打包票：换算规则与学历认定最终以招生办答复为准（页面免责声明已含此口径）
4. **对匹配度的影响**：学分总量不足属于**资格性缺口**——不进匹配分，但必须单独一行解释（type 写"学分门槛"），提醒用户这比课程匹配更硬：匹配分再高也过不了资格审核。

## 第 6 步：写解释（每个匹配项一行）

格式：
```
《课程名》(分数) → 覆盖/部分覆盖 '项目模块或先修要求' —— 一句话说明
```

示例：
- 《GIS原理》(88) → 覆盖 'Foundations of Spatial Data Science' 先修要求 —— 主干课，成绩优秀
- 《遥感导论》(82) → 部分覆盖 'Earth Observation' 模块 —— 覆盖原理层面，缺动手处理经验
- 未覆盖：项目要求统计学基础，成绩单无统计类课程 —— 建议补修 Coursera 统计课 + 在 PS 中说明量化项目经历

## 第 7 步：缺口建议

每条未覆盖项给一条可执行建议：补修课程（含 MOOC）、考试（GRE subject 不常见但可提）、作品/项目替代证明、或直接建议换匹配度更高的项目。

## 边界

- 用户课程清单不全时：先提示补全，用户拒绝则以现有课程估算并把"课程不全"写进档案卡备注
- 跨专业申请（如商科转 GIS）：核心覆盖通常 <40 分，如实给低分并解释"该路径需要预科/证书项目衔接"，不要为了好看虚高分档
