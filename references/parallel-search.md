# 并行检索计划模板（把"穷尽检索"拆成可并行的分片）

用途：当用户目标覆盖多个国家/地区时，**穷尽检索是大工作量**。本文件规定怎么把它拆给多个子 Agent 并行执行，最后在主 Agent 处合并。单 Agent 执行时按同样顺序串行做一遍，不许跳国。

---

## ⛔ 硬规则：一个子代理 = 一个国家（并行度按国家数开，禁止多国打包）

| 情形 | 正确派法 |
|---|---|
| N 个国家 × M 个方向簇 | **N 个子代理，每个代理只背 1 个国家**；该国内 M 个方向簇由这个代理**串行**跑完；**并行度 = 国家数** |
| 单国 × 多方向（如比利时 × 4 簇） | 1 个子代理串行跑完 4 簇——同国共用同一份官方名录，串行反而省抓取次数 |
| 用户只给"欧洲""北欧"等大区词 | 先展开成国家清单，再按国家派代理；大区词本身不是一片 |

**⛔ 禁止的派法**（实测反模式，不许再犯）：

- ❌ **多国打包给一个子代理**："西班牙+意大利一组""德国+荷兰+比利时一组"——一个代理背 3 个国家，结果必然是每国象征性查两条就交差
- ❌ 把同一国拆给多个子代理：重复抓取 + 口径打架（同一学校两个代理给出不同结论）
- ❌ 一个代理只查一国的一个方向簇就算完成：其余方向簇要么没人查、要么被别的代理重复查

**为什么这样派**：多国打包时，子代理会把检索量**摊薄到各国**（"顺手查两条交差"）；一国一代理时，该国的完整穷举（名录枚举 → 逐校核验 → 排除留痕）才有唯一责任人。**同国多簇串行并不浪费**——它们共用同一份官方名录页，串行能复用抓取结果；**跨国打包才浪费**（各国名录完全不同，最后还要在一堆混合结果里按国切分）。

---

## 一、子代理分工规则（分工必须互不重叠）

```
子代理 = 一个国家（该国全部方向簇由它串行跑完）  ← 最小执行单元
```

- **一国一代理**：每个国家/地区一个子代理（比利时 ≠ 荷兰 ≠ 德国），并行度 = 国家数
- **簇内串行**：该国的方向簇（GIS/测绘遥感、城市与规划、交通规划、环境与可持续…）由该代理**按簇依次**跑完，共用同一份官方名录页；**不把同一国拆成多个并行片**
- 每国产出**同构**结果（同一 schema），主 Agent 只需合并、去重、排序
- 同一代理内跨簇撞到同一个项目也要避免：名录底表复用，项目页只进一次

分工清单写法（示例：比利时 1 个代理 + 4 个方向簇）：

| 子代理 ID | 国家 | 方向簇（串行执行） | 主要检索入口 | 产出 |
|---|---|---|---|---|
| agent-BE | 比利时 | ① GIS/测绘遥感 ② 城市与规划 ③ 交通规划 ④ 环境与可持续 | 官方课程名录（Study in Flanders）+ KU Leuven ICFU / ULB·VUB 建筑与规划 / UHasselt IMOB / UGent·ULiège 环境与土地 | 项目条目 → `data[]`，逐簇给出 checkedPages/candidates |

## 二、每个国家子代理的执行契约（照着做）

```
输入：国家、该国方向簇清单（全部，串行执行）、用户档案（GPA/语言/预算/学位年限）
步骤：
0) 先打开该国**官方课程名录**，把该国项目枚举成"名录底表"——底表在该国各方向簇之间**复用**
   （这是"同国串行"最大的省时点，也是禁止把同国拆 parallel 的原因）
1) 按方向簇逐个过底表，每簇记录本页的翻页数/条目数
2) 逐个进项目页，抄 27 项字段（见 finding-schools.md 第三节）
3) 语言核验：只保留符合用户语言要求的项目（用户明确"只筛英授"时才砍掉本地语项目）；
   官方写明荷语/法语/德语等本地语授课的 → 进 exclusions，并原文引用官方表述
4) 交叉核验：项目在招？截止日期？学费口径（本地生 vs 非 EEA/非本地）
5) 输出两份：projects[]（符合条件，27 字段）+ exclusions[]（学校/项目/理由/来源/核验日期）
6) 不得输出任何未核验的数字；无来源的字段留空并在 note 写「待核验」
7) **该国每个方向簇都要有结论**——某簇确实没有项目，就写"该国官方名录内无此方向项目"
   并附名录来源（负向结论也是成果，不许留空）
```

**子代理输出格式**（JSON，便于主 Agent 直接合并）：

```json
{ "country": "比利时", "clusters": [
    { "cluster": "GIS/测绘遥感", "checkedPages": 14, "candidates": 23 },
    { "cluster": "城市与规划", "checkedPages": 11, "candidates": 12 } ],
  "checkedPages": 25, "candidates": 35,
  "projects": [ { ...27 字段同 data-schema.md... } ],
  "exclusions": [ {"school":"","program":"","reason":"","source":"","checkedDate":""} ] }
```

## 三、主 Agent 的合并与验收

1. **合并去重**：按 `学校+项目` 去重（同名项目在不同分片被查到很常见）
2. **补全链接**：`schoolLinks` / `regionLinks` 缺的补齐（build.js 会强制校验，缺了构建不过）
3. **跑门禁**：`node scripts/build.js` 会校验字段完整性、verifiedDate、policyYear、链接覆盖
4. **验收检索量**（finding-schools.md 7.4）：把各国子代理的 `checkedPages` 与 `candidates` 加总，对照下限；**多国任务额外按国分组验收**——每个国家独立达标并产出「国家覆盖表」（finding-schools.md 8.0），不许用全部国家的总平均掩盖某个国家的缩水
5. **★ 数量对账（重跑旧项目时强制，交付前必做）**：跑 `node scripts/compare_results.js <本次data.json> <上次data.json>`，看报告「三、按国入选数对账」段——**某国入选数比上轮下降 >20%、本轮清零、以及新增国家**都会被点名。**每一个都必须逐国交代去向**（进排除清单 + 官方来源 / 回补检索把漏校找回来），并写进国家覆盖表的「对上轮变化」列。**不许只在表里写个数字就交差，更不许静默变少**
6. **汇总排除清单**：所有子代理的 exclusions 合并 → `assets/exclusions.json` → 页面自动渲染成折叠区/表格
7. **产出**：HTML（按需一个总页或每个地区一页）+ Notion 四表 CSV

## 四、并行度与注意事项

并行度 = **保留国数量**（不是方向簇数，也不是分片数）

| 情况 | 做法 |
|---|---|
| 1 国 × 1–2 个方向 | 不拆，单 Agent 串行 |
| 1 国 × 4 个方向 | 1 个子代理串行跑完 4 簇（共用名录底表），不必拆并行 |
| 3 国 × 4 个方向 | **3 个子代理并行**（每国 1 个，各串行自己的 4 簇）——**不是 12 片并行，也不是按大区分组** |
| 用户只给"欧洲" | **先展开成国家清单**（12 大区表），再按国家派代理——不许把"欧洲"当成一个国家，更不许"西意一组""德荷比一组"打包 |

**禁止**：
- ❌ **多国打包给一个子代理**（"西意一组""德荷比一组"）——多国任务最典型的偷懒：检索量被摊薄到各国，每国象征性查两条就交差
- ❌ 把同一国拆给多个子代理（重复劳动 + 口径打架）
- ❌ 一个代理只查一国的一个方向簇就收工（该国覆盖不完整，且名录被重复抓）
- ❌ 合并时丢弃某个国家的结果、或把某国标成"低优先级"跳过——每个保留国都必须真实执行并进入国家覆盖表（finding-schools.md 8.0）
- ❌ 子代理自己补数据（未核验不得写入；发现缺口要回报，由主 Agent 决定再查一轮）
- ❌ 用"这片没查到"代替"这片没查"——每个方向簇必须给出 `checkedPages` 数字
- ❌ **某国入选数比上轮下降 >20% 却不交代去向**（静默变少＝交付不合格；见第三节第 5 条与 compare_results.js 对账段）

## 五、效率提示

- 同一学校的多个项目常在同一目录页 → 每片先抓"名录页"再逐个进项目页，可省一半请求
- 学费/语言/截止三类数据优先核验（它们是判定与筛选的输入），其他字段可后补并标 `verified:false`
- 分片执行前先把 `regionLinks`/`schoolLinks` 的官方入口准备好，子 Agent 直接用，避免各自找入口
