# Notion 模板与定时监控打通（自查看板）

> ⚠️ **本文件是检索线索与核对清单，不是数据结论。**
> 其中的流程、数字、机构名、字段口径都必须由 agent **实时联网核验官网**后才可引用；
> 模型记忆只能决定"去哪里查、查什么"，不得直接充当数据。详见 SKILL.md「铁律零：零记忆交付」。

目的：让用户**自己随时自查**——申请材料勾选、院校日期盯梢、签证流程打勾、政策变动追踪。四张表由脚本从 HTML 模板的同一份 DATA 生成，口径与页面完全一致。

## 一、四张表（导入 Notion 后的结构）

| 表 | 用途 | 关键字段 |
|---|---|---|
| **1. 申请项目总表** | 一校一行，看全局 | 学校/地区/专业/QS/录取档/先修风险/匹配度/学费/生活费/总花费/兼职上限/可计入奖学金/预算档/年缺口/申请时间线/学签/工签/永居/专业官网/招生入口/核验状态/**下一步动作**/备注 |
| **2. 申请与签证材料清单** | 逐项勾选（自查核心） | 阶段/材料项/是否必需/适用地区/出具方/时效要求/**状态**/负责人动作/截止日期/备注 |
| **3. 申请签证时间线** | 每校关键节点 + 通用节点 | 学校/地区/节点/官网时间/**我的计划日期**/状态/**逾期天数**/负责人动作/来源/备注 |
| **4. 地区签证政策库** | 政策速查与复核 | 地区/学签类型/办理时长/学签官方链接/毕业后工签/工签时长/工签条件/永居条件/入籍条件/兼职上限/**政策核验日期**/下次复核 |

## 二、生成与导入步骤

1. 从 HTML 模板（`assets/template.html`）的 DATA 生成四张 CSV（复用页面同一份数据，保证口径一致）
2. 在 Notion 中：`设置 → 导入 → CSV`，逐个导入四张表

> **文件名纪律**：要打包分发 / 跨平台传输的 CSV 一律用 ASCII 文件名（如 `1_application_projects.csv`）。
> 中文文件名在本机没问题，但 zip 的 UTF-8 文件名标志位会被部分解压工具（某些 Linux unzip、Windows 资源管理器特定区域设置）忽略，解压出来是 GBK/CP866 乱码。仅本机自用才可用中文名。
3. 导入后按需改字段类型（Notion 会自动推断，建议手工确认）：
   - 「状态」→ Select（未开始 / 进行中 / 已完成 / 已逾期）
   - 「截止日期」「我的计划日期」「官网时间」→ Date
   - 「是否必需」「已核验」→ Checkbox
   - 「QS排名」「匹配度」「年缺口」→ Number
   - 「专业官网」「招生入口」「学签官方链接」→ URL
4. **建关联（Relation）**：表 2/表 3 的「学校」字段关联到表 1 —— 就能在一所学校页面下看到它的材料与节点
5. 表 1 加看板视图（Board）按「录取档」或「预算档」分组；表 3 加 Calendar 视图按「我的计划日期」

## 三、与定时监控任务打通（重要）

定时任务每次跑完，按如下规则处理结果：

```
① 监控任务用官方源核对：目标院校的申请开放/截止日期、签证预约与政策变化
② 对比"上次记录"（本地看板文件或 Notion 表 4 的核验日期）
③ 有变更 → 分两类处理：
   - Notion 连接可用：更新对应表行（表1 的"下一步动作/截止"、表3 的节点时间、表4 的政策与核验日期），并在"备注"写明变更来源与日期
   - Notion 连接不可用：把变更写入本地 `_变更待同步.md`（含表名/行标识/字段/旧值→新值/来源链接），任务结束时在回复里列出待同步清单
④ 无变更 → 只更新"最后核验日期"，不要制造无意义的改动
⑤ 绝不因为"看起来该更新"就编造日期或政策；无官方来源就标"未确认"
```

## 四、字段与 HTML 页面的对应

| Notion 字段 | HTML/JSON 来源 |
|---|---|
| 录取档 / 先修风险 | `admitVerdict()` 实时判定（保底/主申/冲刺/高风险 + 先修风险叠加） |
| 预算档 / 年缺口 | `budgetCalc()`（gap vs 兼职上限 pt vs 可计入奖学金 sch） |
| 匹配度 / 匹配说明 | `match.score` / `tier` / `explanations` |
| 申请时间线 | `timeline[]` |
| 学签 / 工签 / 永居 / 入籍 | `visa` / `workVisa` / `pr` / `citizenship` |
| 专业官网 / 招生入口 | `links` / `SCHOOL_LINKS[id]` |
| 地区政策链接 | `REGION_LINKS[region]` |
| 政策核验日期 | `verifiedDate` + `visa.verifiedDate` |

## 五、使用建议（给用户的一段话）

- 每周看**表 3 的 Calendar**：哪些节点本周到期、哪些已逾期（逾期天数会自动算）
- 每月看**表 4 的下次复核**：政策类字段到期就该重新核验
- 收到 offer 后主要动作：更新表 1 状态 → 在表 2 勾选签证材料 → 按表 3 推进递签节点

## 六、定时任务模板（两类，可直接用 automation 建）

### 任务 A：院校申请窗口与截止监控（每周一 09:00）

**检查项**
- 读表 1，筛出**未来 30 天内有节点**的项目（开放 / 截止 / 出结果 / 押金）
- 对每个命中项目，用 `WebFetch` 打开其「专业官网」核验：日期是否变动、是否新增轮次、项目是否停招/更名
- 顺带扫一次该地区官方名录（Discover Uni / CRICOS / Hochschulkompass 等），看是否出现**清单外的新项目**（符合条件就加入候选并标注"新增"）

**产出**
- 表 1 对应行更新（时间线、核验日期、备注写明来源与变更）
- `变更日志.md` 追加一条：日期｜学校｜项目｜字段｜原值→新值｜来源链接
- 简报：本周待办 3–5 件 + 每件截止倒计时

### 任务 B：签证与材料节点监控（每月 5 日 10:00）

**检查项**
- 读表 2/表 3，找**未来 60 天内**的待办：体检、资金证明、APS、递签预约、CAS/IPA/CoE/eVAL、住宿申请
- 读表 4，逐地区用官方链接核验学签/工签/永居条目：政策年份、金额、时长、兼职上限是否变化
- **签证预约**：核验目标国使领馆/签证中心的预约渠道与当前等待时间（官方页）

**产出**
- 表 2（状态/截止）、表 3（计划日期）、表 4（政策与核验日期）更新
- `变更日志.md` 追加
- 简报：需办理/预约清单（附官方入口链接）+ 政策变更提醒

### 两条硬规则（写进任务 prompt）

1. **只信官方源**：院校官网、移民局官网；禁止中介站与聚合站；无官方来源就标「未确认」，**不许编造日期或政策**
2. **Notion 写入分两种模式**：能用 `mcp__notion__*` 工具就直接写库；不能用就只改本地 CSV + `变更日志.md`，并在简报里说明「需先在连接器启用 Notion 工具」——**不得假称已写入**

### 变更日志格式（追加式，放在工作区根目录）

```
## 2026-10-09
- 帝国理工 MSc Computing：截止 2026-11-15 → 2027-11-14（轮次页更新）｜https://...
- 英国：Graduate Route 2 年 → 18 个月（gov.uk）｜https://...
- 新增候选：港理工 MSc Aviation（清单外，已加入评估）
```
